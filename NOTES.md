# Cyber Speedway (Sega Saturn, Sega / Nextech 1995; JP Gran Chaser) decompile notes
Research only, non-commercial; never publish game files, bins or dumps. Same method as Scorcher/AMOK (skill scorcher-re).
## Setup (10-12)
- Source: the user's download Downloads/Cyber-Speedway_SEGA-Saturn_EN.zip (Europe, 21 tracks: Track 01 data 61410720 bytes, tracks 02-21 CD audio, not extracted).
- image/ = Track 01 .bin + .cue. cd/ = 167 files (350.7 MB) via Scorcher tools/isoextract.py <bin> cd 2352.
- IP header: product MK-81205 V1.000 1995-09-25, title "CYBER SPEEDWAY", 1st read address field at header +0xf0 = 06 02 00 00 (0x06020000).
- Program candidates: AUTOEXEC.BIN 350244 (starts with SH-2 code d0 03 6f 03 ..., literals 0x06012014 / 0x060ffffc), MAIN_SE.BIN 400418, MENU.BIN, MENU_SE.BIN, END.BIN, TITLE_OP.BIN, PROLOGUE.BIN, TEST.BIN, STATION.BIN, ROOM1-6.BIN; sound driver SDDRVS.TSK; maps MAP*_*.BIN, textures TEX*.BIN, FINAL_D.CPK (movie).
- Next: find each program's load address (who loads it, from AUTOEXEC strings / file-name table), create Ghidra project Documents/CyberSpeedway/ghidra (SH-2 BE), run FindSh2Functions, name pipeline.
- Module scheme (10-12): every program file (AUTOEXEC, MENU, MAP*_*/MAPW*, ROOM1-6, STATION, END, PROLOGUE, TITLE_OP, SMPCPK4) starts with the same stub: r15 = 0x060ffffc, jmp 0x06012014 -> each loads at 0x06012000 and replaces the previous one (overlay programs, not libraries). File-name references: AUTOEXEC -> MENU_SE/SMPCPK4/TEMP/XSDDRVS.TSK; MENU -> all 23 MAP files, PROLOGUE, TITLE...; ROOM* -> MAP*, STATION, END; STATION -> P1-5.DAT + pilot .DATs (DRUKE, JAQUOE, NARD, SKEMETT, ZAHANECK); MAP* -> TEX/GG8|GG9 files, ROOM2-6, END, MENU. MAP* = race program (MAP = 1P? MAPW = W variant, TEX2W). AAAAA000.BIN references AUTOEXEC/AAAAA001/TEST/SDDRVS0 (boot/test loader?).
- Boot (10-12): AAAAA000.BIN stub jumps 0x06020014 (= 1st read address 0x06020000), AAAAA001.BIN jumps 0x06004014 (loads at 0x06004000). Overlays diverge from each other after 0x61 bytes (shared library, different link addresses).

## Ghidra (10-12)
- Project ghidra/CyberSpeedway.gpr. Runner ghidra/csprun.sh <abs log> <args> (SP=<path> overrides -scriptPath; default ghidra/scripts).
- Import: -import cd\X.BIN -processor SuperH:BE:32:SH-2 -loader BinaryLoader -loader-baseAddr 0x06012000 -postScript FindSh2FunctionsMem.java (whole-block range), then a plain -process X.BIN analysis run, then Amok ExportFuncInfo -> ghidra/funcinfo_X.tsv.
- First batch: AUTOEXEC, MENU, MAP1_1, ROOM1, STATION, END.
- Import results (FindSh2FunctionsMem + analysis, funcinfo_X.tsv): AUTOEXEC 463, MENU 519, MAP1_1 520, ROOM1 494, STATION 424, END 472 functions. No errors in the imp_/an_ logs.
- Strings are sparse (funcinfo S lines: AUTOEXEC 9, MAP1_1 32, ROOM1 61, MENU 164 = menu/result texts, file names MAPn.BIN MAPWn.BIN PROLOGUE.BIN MENU_SE.BIN SDDRVS.TSK).
- Cross-overlay matching: tools/xmatch.py <ghidra> <cd> PROG... hashes each function body with bra/bsr/bt/bf and PC-relative mov displacements masked -> ghidra/xmatch6.txt: 324 shared bodies, 247 in all six (per prog shared: AUTOEXEC 306, MENU 317, MAP1_1 253, ROOM1 308, STATION 275, END 313). MENU and ROOM1 put the shared low code at the same addresses; MAP1_1 moves it; the SGL-like library sits at the program end in every overlay.
- tools/xprop.py <ghidra> <xmatch> PROG... copies a hand line to every twin without one (comment "(twin PROG:addr)").
- Naming plan: dump all six (Amok CsDumpAll -> ghidra/decomp_X.c), Sonnet agents name AUTOEXEC first (prompt ghidra/scripts/n1_prompt.txt, output hand_AUTOEXEC.txt), xprop to the rest, then agents name only the leftover FUN_ of each other overlay.
- Name round 1 (10-12): five Sonnet agents named AUTOEXEC -> ghidra/hand_AUTOEXEC.txt 463 lines (188 provisional), applied: 0 FUN_ left. Twins via xprop + ApplyNames: MENU 314 (FUN_ left 204), MAP1_1 251 (269), ROOM1 306 (188), STATION 282 (142), END 315 (157). Library content seen: libgcc div/shift helpers, memcpy/strcmp, VDP1 command builders, pad input, sound command queue (snd_Cmd*), GFS file system + CD block cdc_* commands, SH-2 DMAC, ISO9660 dir parser, sin/cos tables.
- Round 2: leftovers sliced to ghidra/slices/<P>_sN.c (twins of the 18 shared non-AUTOEXEC groups skipped via slices/excl_<P>.txt; xprop fills them after).
- GOTCHA: one Ghidra job per project. A wait loop on a background job's output must match its final line, not an earlier line with the same prefix (an apply hit "Unable to lock project" that way).
- Round 2 done (10-12): 16 Sonnet slices + 2 by hand (ROOM1 0x0601abd0 fp_DoubleToDigits, 0x0601b3f8 fp_UnpackDouble), merged into hand_<P>.txt; duplicate names suffixed _2.. per program. Hand lines: AUTOEXEC 463 (188 provisional), MENU 518 (233), MAP1_1 520 (211), ROOM1 494 (195), STATION 424 (206), END 472 (162).
- tools/xunify.py <ghidra> <conflict lines>: twins named differently by different agents get the first member name (26 groups unified). Use grep "^conflict " (with the space) on xprop output; "conflicts N" is the count line. 8 conflicts stay = duplicated bodies inside one program, named _2.._4 the same way in every overlay.
- Applied round 2 (10-12): FUN_ left 0 in all six (AUTOEXEC 463, MENU 519, MAP1_1 520, ROOM1 494, STATION 424, END 472). Next: import the other MAP/ROOM overlays + AAAAA000/AAAAA001, xmatch + xprop, name leftovers the same way.
- Second import (10-12): 32 more code files imported (scratchpad cspimport2.sh): MAP1_2..MAP6 ~520 functions each, MAPW* ~528, ROOM2-6 ~494, PROLOGUE 415, TITLE_OP 124, SMPCPK4 520, AAAAA000 274 (base 0x06020000), AAAAA001 256 (base 0x06004000). Data only (not imported): TEX*, GG*, MAIN_SE, MENU_SE, MME, QQQ, TEST, TEMP, GCSNDMAP.
- xmatch.py: per-prog base for AAAAA000/001; --loose masks 0x060xxxxx literal words (size >= 24) because builds shift addresses: MAP twins go from ~330 to ~440 of 520. Loose groups holding two functions of one program are false matches (accessors of different globals) and are dropped -> ghidra/xmatch_loose1.txt. Order: xprop strict xmatch_all.txt, then xmatch_loose1.txt.
- Wave 3 (10-12): 8 Sonnet agents named 342 leftovers in reps MAPW1_1 SMPCPK4 MAP4_1 PROLOGUE TITLE_OP ROOM3 AAAAA000 AAAAA001 (ghidra/reps.txt). tools/xrank.py fixes groups with 2+ functions of one program (A/B accessors) by address rank vs a reference program. After xprop: reps 0 left; MAP* 25-31, MAPW* 22-36 (MAPW6_1 51), ROOM2/4/5/6 11-14.
- tools/xpos.py <ghidra> <ref> <targets>: names leftovers between two same-named anchors when count and sizes match in order (comment (pos REF:addr)). Refs used: MAP1_1 for MAP*, MAPW1_1 for MAPW*, ROOM3 for ROOM2/4/5/6. After it + xprop: MAP* 2-13, MAPW* 1-17 (MAPW6_1 35), ROOM2/5/6 1-2, MENU 1. TODO at the end: stub_<addr> names carried to another program keep the source address; rename to own address.
- Wave 4 (10-12): reps4 MAPW6_1 MAPW2_1 MAPW4_2 MAP3_1 MAP5_1, 95 functions by 3 Sonnet agents. Wave 5: the other 18 programs with leftovers (ghidra/reps5.txt + MAP1_2), 125 functions by 3 agents (slices/w5_<P>_s1.c -> hand_w5_<P>_s1.txt). tools/dedupe.py (one line per address, repeated names get _2..), tools/stubfix.py (100 stub_<addr> names carried from another program renamed to their own address). After wave 5 every hand_<P>.txt covers every function of its program (MENU 518 of 519, the known harmless gap). Remaining xprop conflicts are in-program duplicates named _2.._N the same way in every overlay. MAP1_2 0x0603e140 / 0x0603e192 are misdecoded data (provisional names).
- Chain used after each wave (all 38): dedupe, xprop xmatch_all, xprop xmatch_loose1, xunify on "^conflict " lines, xrank MAP1_1, xpos (MAP1_1 / MAPW1_1 / ROOM3), xprop again, stubfix, dedupe, then scratchpad cspapply.sh on all 38.
- Provisional review (10-12): tools/provreview.py <ghidra> <N> <prefix> collected the 382 distinct origin provisional names (7250 lines incl. twins) with bodies into ghidra/review/prov_s*.txt; Sonnet agents wrote res_s1, res_s2a, res_s2b, res_s2c (grounded tail of the first s2 run; its first 101 verdicts were redone after the agent lost context), res_s3, res_s4 -> res_all.txt: 276 CONFIRM, 17 RENAME, 89 UNSURE. tools/provapply.py <ghidra> res_all.txt: 5546 lines lose the provisional marker, 81 renamed (comment ends (was old)); 1631 provisional lines remain (the UNSURE names + twins). Backup of the hand files before: ghidra/review/bak/. Applied with scratchpad cspapply.sh on all 38 (review_apply.log).
- Unsure second pass (10-12): tools/provctx.py <ghidra> <res_all.txt> <N> <prefix> writes each UNSURE function with up to 3 caller bodies (callers from funcinfo C lines plus literal-pool words holding the address; PTR_ pool slots resolved to &name / &DAT_ from cd/<P>.BIN) into ghidra/review/unsure_s1..4.txt; prompt ghidra/review/prompt2.txt; results res2_s*.txt, apply with provapply.py.
- Unsure second pass applied (10-12): res2_all.txt = 18 CONFIRM, 41 RENAME, 30 UNSURE of 89; provapply: 373 lines confirmed, 693 renamed (incl. twins); 565 provisional lines remain (30 names + twins). Backup before: ghidra/review/bak2/. Ghidra apply done: FUN_ left 0 in all 38 (review2_apply.log).
- Third pass (10-13): all 30 unsure settled, 0 provisional names left (26 lines keep only a "(was ..._provisional)" history note). The 6222-byte routine pairs are unrolled initialisers writing 1024 pointers (0x80 column stride) into a work table at base+4, decoded from raw bytes with scratchpad storeseq.py: sys_InitPointerTableA/B. MAP1_1 0x06020074 car_UpdateAll_Large -> car_UpdatePlayer (one human car per call, index 0/1). sys_GetConstant_* and cd_GetConstant -> cd_GetDataPortAddr (returns 0x25818000); sys_ReadShortGlobal_* -> cd_ReadHirq. Verdicts in ghidra/review/res3_mine.txt, res3_small.txt, res3_big.txt; backup ghidra/review/bak3/. Ghidra apply: 38x FUN_left 0. Gotcha: provapply strips an all-digit _<addr> suffix as if it were a dedupe suffix (sys_LargeRoutine_06016200), so check renames of names ending in a hex address.
